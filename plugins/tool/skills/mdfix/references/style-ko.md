## 문체

서술 문단은 합니다체(`-합니다`, `-습니다`)로 쓴다. 경어체 중 하십시오체에 해당하며, 해요체는 쓰지 않는다. 토스증권 Open API, 토스페이먼츠 API 레퍼런스, AWS·MDN 한국어 문서가 같은 방식이다.

| 원문 상태 | 처리 |
| --- | --- |
| 이미 합니다체 | 어미는 손대지 않음 |
| 평서체(`-한다`, `-이다`) | 합니다체로 변경 |
| 해요체(`-해요`, `-예요`, `-이에요`) | 합니다체로 변경 |
| 여러 문체 혼재 | 전부 합니다체로 통일 |

- 코드 주석, 인용문, 사용자 입력 예시, UI 문구 원문은 그대로 둔다
- 절차를 풀어쓴 서술 문단("먼저 A. 그 다음 B. 마지막으로 C.")은 어미를 고치기 전에 번호 목록으로 바꾼다. 어미만 바꾸면 단계 구분이 여전히 안 보인다

## 목록과 표 셀

목록 항목과 표 셀은 명사구로 쓰고 마침표를 찍지 않는다. 사실이 둘 이상이면 `. `으로 잇는다. 같은 어미가 항목마다 반복되면 정작 다른 부분이 눈에 안 들어온다.

```
- 캐시 만료 시간을 10분으로 늘렸습니다        →  - 캐시 만료 시간 10분으로 연장
- 관리자만 삭제할 수 있도록 해야 합니다        →  - 삭제는 관리자만 가능
- 로그 보관 기간이 정해지지 않았어요           →  - 로그 보관 기간 미정
- 심볼릭 링크는 지원하지 않는다                →  - 심볼릭 링크 미지원
```

```
| Architecture | 시스템 구성 요소, 레포 구조와 소유 팀, 환경, 외부 의존 |
| holdings     | 보유 종목 목록. 보유 종목이 없으면 빈 배열 |
```

- 명사로 끝낼 수 있으면 명사로 끝낸다(`연장`, `가능`, `미정`). `~함`·`~됨`은 명사로 끝내면 뜻이 어색할 때만 쓴다
- 원인·이유처럼 인과를 설명해야 하는 항목은 합니다체 문장으로 쓰고 마침표를 찍는다. 한 목록 안에서는 한쪽으로 맞춘다
- 제목형 셀(ADR 제목, 결정 요약)은 원문 문장을 그대로 둔다. 예: `개발 문서는 두레이 위키에서 관리한다`
- 한 항목에 문장이 여럿이면 [문장 단위 줄](structure.md#문장-단위-줄) 규칙대로 줄을 바꾼다

## 구어·속어

판단 기준: 사전 뜻과 다른 비유로 쓰인 일상어·은어·인터넷 구어는 모두 대상이다. 아래 표는 예시이며 전체 목록이 아니다. 표에 없는 단어도 이 기준으로 직접 찾는다.

| 쓰지 않음 | 대신 |
| --- | --- |
| 죽였다, 킬했다 | 종료, 중단 |
| 짜른다, 날렸다 | 제거, 삭제 |
| 갈아엎었다, 뒤엎었다 | 재작성, 전면 수정 |
| 박았다, 꽂았다 | 적용, 추가 |
| 먹혔다, 안 먹힌다 | 동작함, 동작하지 않음 |
| 삽질, 뻘짓 | 시행착오 |
| 레알, 개~, 존~, ㅋㅋ, ㅎㅎ | 삭제 |
| 박제(값을 박제) | 스냅샷, 시점 값 저장, 버전 고정 |
| 태우다(배치를 태우다), 때리다(API를 때리다) | 실행, 호출 |
| 털다(로그를 털다) | 조회, 추출 |
| 땜빵 | 임시 조치 |

이모지는 헤딩과 본문에서 뺀다. 표 안에서 상태 표시(✅/❌)로 쓰여 뜻이 명확하면 남긴다.

정의된 용어도 교체한다. 헤딩·표 항목명·굵은 라벨로 정의된 비유어도 대상이며, 문서 안의 모든 등장 위치를 같은 대체어로 한꺼번에 바꾼다.

- 다이어그램 블록(mermaid, PlantUML 등)의 라벨 문자열에 같은 단어가 있으면 라벨 글자만 같은 대체어로 바꾼다. 노드 ID, 화살표, 구조는 건드리지 않는다
- 소스 코드, 식별자, 설정 키, URL처럼 바꾸면 동작이 달라지는 곳에 쓰인 단어는 바꾸지 않는다. 이 경우만 보고의 "용어 검토 권장"에 대체어 후보와 위치를 적는다
- 보고에 "용어 교체: 박제 → 스냅샷 (본문 N곳, 다이어그램 라벨 M곳)" 형식으로 적는다

속어가 담고 있던 사실은 남긴다. "삽질을 꽤 했다"는 "원인 파악에 시간 소요"처럼 사실로 바꾸고, 감정 표현만 지운다.

## AI slop

문서를 기계가 쓴 티 나게 만드는 패턴. 보이면 지운다.

| 패턴 | 예 | 처리 |
| --- | --- | --- |
| 이중 피동 | ~되어지다, ~게 되어지다 | ~되다. [국립국어원 답변](https://www.korean.go.kr/front/onlineQna/onlineQnaView.do?mn_id=216&qna_seq=317346&pageIndex=1) |
| 번역투 | ~에 대해, ~을 통해, ~에 있어서 | ~을, ~(으)로, ~에서 |
| 공허한 수식어 | 강력한, 효율적인, 원활한, 손쉽게, 매끄러운, 혁신적인 | 삭제하거나 수치로 교체 |
| 중요도 부풀리기 | 핵심은 ~입니다, 주목할 점은, 매우 중요합니다 | 사실만 남김 |
| 대조 구문 | 단순히 X가 아니라 Y입니다 | Y를 바로 진술 |
| 요약 마무리 | 결론적으로, 요약하자면, 앞으로도 지속적으로 개선해 나가겠습니다 | 문단째 삭제 |
| 대명사·지시어 과다 | 이를, 그것을, 해당 ~ 반복 | 대상 이름을 직접 씀 |
| 문장 중간 굵게 | 이 설정은 **반드시** 필요합니다 | 굵게 해제. 목록 맨 앞 라벨과 표 셀의 굵게는 대상 아님 |

이식성 검사: 어떤 문장을 다른 회사, 다른 제품 문서에 그대로 옮겨도 말이 되면 그 문장은 내용이 없다. 지우거나 이 문서에만 해당하는 숫자·이름·동작으로 바꾼다.

```
이 가이드를 따라가면 손쉽게 배포 환경을 구성할 수 있습니다.   →  (삭제)
강력한 캐시 계층으로 응답 속도가 개선됩니다.                    →  캐시 적중 시 응답 시간 120ms → 15ms.
```
