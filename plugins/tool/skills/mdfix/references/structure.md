## 표 전환

목록 항목들이 같은 종류의 속성을 둘 이상 반복하면 표로 바꾼다. 속성이 반복된다는 것은 항목끼리 비교하라는 뜻이고, 비교는 열로 정렬돼야 눈으로 된다.

| 목록 형태 | 판정 |
| --- | --- |
| `이름 — 속성1, 속성2` 반복 (3개 이상) | 표 |
| `**라벨**: 설명` 반복 (3개 이상 연속) | 표. 라벨과 설명이 이미 두 속성 |
| 설명 끝에 같은 종류의 꼬리 정보 반복 (`[#12]`, 담당자, 근거, 기한) | 그 꼬리 정보를 별도 열로 |
| 항목마다 사실 하나뿐인 단순 나열 | 불릿 유지 |
| 항목 2개 이하 | 불릿 유지. 표 틀이 내용보다 커짐 |
| 순서가 의미 있는 절차 | 번호 목록 |

`**라벨**: 설명` 형태를 "항목마다 단일 사실이라 불릿 유지"로 판정하지 않는다. `scripts/check.py`의 `라벨 불릿 묶음`과 `속성 반복 목록`이 이 대상을 찾아준다. 검사는 `이름 — 속성, 속성`과 `**라벨**: 설명` 형태만 잡으므로, 다른 구분자로 속성을 반복하는 목록은 직접 읽어서 찾는다.

```
- 웹 서버 — 4 vCPU, 메모리 8GB, 2대          | 역할   | vCPU | 메모리 | 대수 |
- DB — 8 vCPU, 메모리 32GB, 1대 (+복제 1)     | ------ | ---- | ------ | ---- |
- 배치 — 2 vCPU, 메모리 4GB, 1대              | 웹 서버 | 4    | 8GB    | 2    |
```

```
* **보관 기간**: 원본 로그 30일, 집계 1년 [#41]     | 항목      | 정책                  | 이슈 |
* **접근 권한**: 운영팀만 원본 조회 가능 [#41]     | --------- | --------------------- | ---- |
* **마스킹**: 전화번호 뒤 4자리만 노출 [#57]       | 보관 기간 | 원본 로그 30일, 집계 1년 | #41  |
```

열 구성:

- 꼬리 정보는 그 정보가 있는 행이 절반 이상일 때만 별도 열로 뺀다. 절반 미만이면 셀 끝에 그대로 둔다. 빈 칸을 `-`로 채운 희소 열은 정보보다 잡음이 크다
- 문서 안에서 같은 역할의 표(장마다 반복되는 "설계 포인트", "위험 요소" 등)는 하나의 표처럼 판정한다. 그 표들의 최종 행(긴 항목을 나눈 뒤의 행) 기준으로 위 조건을 따져 전부 열로 빼거나 전부 셀 끝에 두고, 열 이름과 순서를 맞춘다
- 같은 정보는 열과 셀 중 한 곳에만 적는다. 열로 뺐으면 셀 안의 같은 표기는 지운다
- 열로 뺀 뒤 그 정보가 없는 칸은 비워 둔다. `-`나 `없음`으로 채우지 않는다

셀 길이는 [줄 길이 100자](#줄-길이-100자) 기준을 셀마다 적용한다.

## 문장 단위 줄

화면에서 한 줄에 한 문장이 보이게 한다. 문단 길이와 상관없이 문장이 둘 이상인 서술 문단은 모두 대상이다.

| 문단 상태 | 처리 |
| --- | --- |
| 문장 3개 이상, 각 문장이 독립된 사실 | 명사구 목록으로 전환 |
| 문장 2개 이상, 앞뒤 문장이 이어지는 설명(원인→결과, 배경→결정) | 문단 유지. 마지막 문장을 뺀 각 문장 끝에 공백 2칸 붙이고 개행 |
| 문장 1개 | 그대로 |

같은 역할의 문단(장마다 반복되는 도입 문단 등)은 하나를 목록으로 바꾸면 나머지도 같은 방식으로 맞춘다.

```
원인은 커넥션 풀 고갈이었습니다. 배치가 타임아웃 없이 커넥션을 잡았습니다. 서버 재시작으로 복구했습니다.
→
원인은 커넥션 풀 고갈이었습니다.␣␣
배치가 타임아웃 없이 커넥션을 잡았습니다.␣␣
서버 재시작으로 복구했습니다.
```

(`␣`는 공백 한 칸. 실제 파일에는 공백 2칸을 넣는다.)

- 문장 끝은 종결 어미 뒤의 `.` `?` `!`다. 소수점(`3.5`), 버전(`v1.2`), 약어(`e.g.`), URL·코드 스팬 안의 `.`, 괄호 안 문장은 문장 끝이 아니다
- 목록 항목 안에 문장이 둘 이상이면 같은 방식으로 공백 2칸 줄바꿈을 하고, 이어지는 줄은 항목 내용 시작 위치에 맞춰 들여쓴다. 문장이 셋 이상이면 하위 항목으로 나누는 것을 먼저 검토한다
- 표 셀 안에서는 줄바꿈하지 않는다. 문장이 여럿이면 `. `으로 이어 쓴다
- 공백 2칸은 눈에 보이지 않고 일부 에디터가 저장 시 지운다. 재검사의 `문단 안 줄바꿈` 항목으로 빠진 곳을 확인한다

## 줄 길이 100자

렌더링된 글자 수 기준으로 한 줄 100자를 넘기지 않는다. 문서 전체 줄 수에는 제한이 없다.

글자 수를 셀 때:

- 링크 `[보이는 글자](URL)`는 보이는 글자만 센다. 참조식 링크 `[글자][ref]`와 이미지 대체 텍스트도 같다
- `**`, `*`, `` ` ``, `~~` 같은 서식 기호, 목록 기호, 헤딩의 `#`, 줄 끝 공백 2칸은 세지 않는다
- 한글·영문·숫자·공백 모두 한 글자로 센다
- 표는 셀마다 센다. 행 전체 길이는 열 수에 따라 달라지므로 대상이 아니다
- 코드블록은 대상이 아니다

100자를 넘을 때 처리 순서:

1. 문장 안의 군더더기를 지운다 (AI slop, 반복 표현, 지시어)
2. 그래도 넘으면 두 문장으로 나눈다. 나누는 자리는 원인과 결과, 조건과 처리처럼 의미가 갈리는 곳이다
3. 표 셀이면 문장을 명사구로 줄인다. 그래도 넘으면 사실 단위로 행을 나눈다(`탈퇴 처리`, `탈퇴 처리: 이력 보관`처럼 항목명을 이어 받음). 단계·대안처럼 순서가 있는 내용만 항목 전체를 표 바로 아래 하위 목록으로 뺀다. 셀 일부만 떼어 옮기면 한 항목이 두 곳으로 흩어진다
4. 고유명사 나열이나 긴 식별자처럼 나눌 수 없는 줄은 그대로 두고 보고에 적는다

`scripts/check.py`의 `100자 초과 줄`이 렌더링 기준 글자 수로 대상을 찾아준다.

## 중복 통합

같은 말을 다르게 반복하는 문단은 하나로 합친다. 문서 길이와 상관없이 항상 적용한다.

- 도입부 여러 문단이 같은 목적을 각각 설명하면 한 문장으로 합친다
- 본문 곳곳의 가정·미결 사항과 문서 끝 요약 표처럼 같은 사실이 두 곳에 있으면 자세한 쪽 한 곳에 남기고 다른 쪽은 참조로 바꾼다
- 예시는 지우지 않는다. 예시 수를 줄이는 것은 정보 삭제다

## 정보 보존

- 숫자, 날짜·시각, 이름, ID, 이슈·질문 번호(`#41`, `Q3`), URL, 코드 식별자는 하나도 빠뜨리지 않는다
- 사실을 지웠으면 보고의 "빠진 내용"에 무엇을 왜 지웠는지 적는다
- 코드블록(mermaid 등 다이어그램 포함) 내용은 바꾸지 않는다. 다이어그램 라벨의 비유 은어 교체만 예외([style-ko.md](style-ko.md#구어속어))
