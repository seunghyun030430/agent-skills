# 확인 결과 보고 형식

조사·확인한 결과를 메신저, 두레이 댓글 같은 곳에 그대로 붙여 넣을 짧은 보고문으로 만든다.

## 형식

```
확인 요청주신 <대상> <주제> 정리 드립니다.

## 증상

- <무엇이 문제로 보고됐는지, 재현 조건, 규모>

## <근거 섹션 이름: 확인 내용 / 그라파나 그래프 / 로그 분석 등>

- <확인한 사실과 수치>

## 결론

- <판단, 조치한 것, 필요한 후속 조치와 담당>
```

## 예시

```
확인 요청주신 그라파나 noworks mico 클러스터 정리 드립니다.

## 증상

신규 사용자가 기본팀에 들어갔을때 기존 클라이언트가 하단 api 모두 호출 (총, 2000건)

- GET /api/v4/users/9136
- GET /api/v4/users/9136/status
- POST /api/v4/users/status/ids

## 그라파나 그래프

- WS-Active Connections: 웹소켓 수가 아닌 nginx 컨트롤러의 연결수
- 클라이언트가 동시에 요청을 보내며 컨트롤러마다 1분간 2배로 증가

## 결론

- 패널명 변경, WS-Active Connections -> Ingress Active Connections
- 주기적으로 발생하는 현상이며 접속자가 많은 상황에서 이슈 발생할 수 있기 때문에 개발검토가 필요해보입니다.
```

## 작성 규칙

- 첫 줄은 "확인 요청주신 <대상> <주제> 정리 드립니다." 한 줄로 연다
- 섹션은 `##` 제목 3개 안팎. 증상 → 근거 → 결론 순서
- 본문은 `-` 목록으로 짧게. 한 항목에 한 사실
- 굵게(`**`), 기울임(`*`), 표, 이모지, 인용(`>`)을 쓰지 않는다. 강조가 필요하면 문장으로 쓴다
- 수치는 측정한 값만 쓰고 기준(기간, 대상)을 함께 적는다. 확인하지 못한 것은 확인 못 했다고 쓴다
- 문체는 "~입니다", "~필요해보입니다" 같은 보고체. 길게 설명하지 않는다
- 결론에는 다음 행동과 누가 할지(개발 검토, 네트워크 담당 확인 등)를 넣는다
- 비밀번호, 토큰, 키 같은 비밀 값은 넣지 않는다
- 결과는 바로 붙여 넣을 수 있게 코드블록 없이 본문 그대로 준다
