# 템플릿 모음

study가 문서 레포를 세팅할 때 사용하는 골격. `<...>`는 실제 값으로 치환한다.
주제·상황에 맞게 가감하되, 작성 원칙(SKILL.md)을 유지한다.

---

## 문서 템플릿 (`0N-*.md`)

```markdown
# <문서 제목>

> <한 줄 핵심 요약 — 결론 우선>

## 개요 / 정의

<무엇인지, 왜 쓰는지>

## <핵심 섹션>

| 항목 | 내용 |
| --- | --- |
| ... | ... |

> "원문 인용" — *출처*

## 사용법 / 예시   ← 해당 문서일 때만

\```<언어>
<최소 예제>
\```

## 이슈 / 안티패턴 / 주의   ← 해당 문서일 때만

- <한계나 흔한 실수>

## 출처

- <1차 출처 URL>

---
*조사 기준일: <YYYY-MM-DD>. <신뢰도/검증 메모>*
```

## README.md 템플릿

비교/요약 표 + 문서 인덱스 + 출처가 핵심이다.

```markdown
# <주제> 정리

<한 줄 소개>. 조사 기준일 **<YYYY-MM-DD>**.

## 한눈에 보기

<단일 주제면 핵심 요약 표, 여러 대상 비교면 대상별 비교표>

| 항목 | 내용 |
| --- | --- |
| ... | ... |

## 문서 인덱스

| 문서 | 다루는 것 |
| --- | --- |
| [01-overview.md](./01-overview.md) | 개요 — 개념·정의·목적 |
| [02-architecture.md](./02-architecture.md) | 동작 원리·구조 |
| [03-usage.md](./03-usage.md) | 사용법·설치·예시 |
| [04-issues.md](./04-issues.md) | 이슈·한계·안티패턴 |

## 출처 (1차)

- <공식 문서 URL>
- <레포 URL>

---
*이 문서는 학습·정리 목적의 요약이다. 정확한 동작/옵션은 항상 위 공식 출처를 확인할 것.*
```

### 여러 대상을 디렉토리로 나눈 경우

대상별로 디렉토리(`<대상>/0N-*.md`)를 두면, README 인덱스는 대상별 표를 반복하고 링크 경로에 디렉토리를 포함한다. 상대경로를 틀리지 않도록 주의.

```markdown
## Goose

| 문서 | 다루는 것 |
| --- | --- |
| [01-overview.md](./Goose/01-overview.md) | 개요 |
| [02-architecture.md](./Goose/02-architecture.md) | 구조 |

## Hermes

| 문서 | 다루는 것 |
| --- | --- |
| [01-overview.md](./Hermes/01-overview.md) | 개요 |
| [02-architecture.md](./Hermes/02-architecture.md) | 구조 |
```

문서 → 문서 링크도 같은 디렉토리 안이면 `./02-architecture.md`, 다른 대상이면 `../Hermes/01-overview.md`처럼 정확히 적는다.

## CLAUDE.md 템플릿

이 문서 레포에서 이후 작업할 때 따를 규칙. (study 자체의 작성 원칙을 레포에 명문화)

```markdown
# CLAUDE.md

## 이 레포의 목적

"<주제>"를 정리하는 문서 중심 저장소다. 코드 프로젝트가 아니라 지식 정리/문서화가 핵심이며,
정확성과 출처가 코드 실행보다 우선한다.

> 정리할 구체적 범위는 사용자가 지정한다. 임의로 문서를 양산하지 말 것.

## 작성 원칙

- **사실 기반**: 사실 주장에는 1차 출처(공식 문서·논문·원문) URL을 함께 단다.
- **추측 금지**: 확신이 없으면 "확인 필요" 또는 "모름"으로 명시.
- **결론 우선**: 결론을 먼저, 근거를 뒤에.
- **비교는 표로**: 선택지·개념이 여러 개면 비교표로.
- **균형**: 권장 사항뿐 아니라 안티패턴·한계·주의사항도 함께.
- **용어**: 기술 용어·고유명사는 원문 그대로, 한글 설명을 곁들인다.

## 문서 컨벤션

- 모든 문서는 Markdown(`.md`). 본문 서술은 한국어, 코드·식별자·고유명사는 원문.
- 제목 계층은 `#`(문서당 1개) → `##` → `###` 순으로만.
- 외부 출처는 인라인 링크 또는 문서 하단 "출처" 섹션에 모은다.
- 날짜는 절대 표기(예: 2026-06-10). 상대 표현 지양.

## 커밋 규칙

- 문서 1개 = 커밋 1개. 메시지는 `docs: <한글 설명>`.
- 관련 파일만 스테이징(`git add <파일>`), `git add -A` 지양.

## 작업 시 주의

- 요청 범위 안에서만 작업. 문서 과잉 생성·과잉 리팩토링 금지.
- 기존 문서를 고칠 때 출처와 사실관계를 먼저 확인하고 수정한다.
```

## git 세팅 명령 메모

```bash
# 레포 루트가 현재 디렉토리인지 확인 (상위 레포의 하위면 결과가 cwd와 다름)
git rev-parse --show-toplevel 2>/dev/null

# 없으면 초기화 (기본 브랜치 main)
git init -b main

# user 설정 확인 — 없으면 커밋이 실패한다
git config user.name
git config user.email

# 기존 레포면 dirty/staged 변경 확인 (무관 변경은 건드리지 않음)
git status --short

# 문서별 커밋 (관련 파일만 스테이징)
git add 01-overview.md
git commit -m "docs: <주제> 개요 문서 추가"

# user 미설정 시 전역 설정을 바꾸지 않고 우회 커밋
git -c user.name="study" -c user.email="docs@local" \
    commit -m "docs: <주제> 개요 문서 추가"

# 최종 확인
git log --oneline
```
